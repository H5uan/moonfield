# Agent Note: Editor action interface

Status: implemented

[English](2026-10-14-editor-action-interface.md)

## Problem

[契约加固提案](../../proposed/architecture/2026-10-14-architecture-contract-hardening.md)
要求 UI、自动化和撤销共用一个执行接口。针对新建实体记录逆操作时，重做产生新的
实体代际后必须刷新逆操作。允许无补偿的删除或文件写入的批次不能承诺失败回滚。

## Decision

**用户动作和补偿使用不同类型。** `EditorAction` 表达导入、场景加载/保存、
变换及反射字段编辑、删除及可逆批次。`EditorUndo` 表达恢复值、移除新建根实体及按序
执行的补偿组。`ActionOutcome` 返回受影响实体、状态和可选补偿。
`perform` 记录成功动作；`record` 合并已完成的 gizmo 手势。

**批次在执行前检查可逆性。** 嵌套的 `DeleteEntity` 和 `SaveScene`
在任何步骤执行前被拒绝。可逆批次失败后逆序执行已完成步骤的补偿，并收集所有
补偿错误。`ActionError::Rollback` 同时保留原始失败和这些错误。场景模板和
组件 hook 可以产生无关副作用；保证不包含这些副作用及加载缓存保留的资产。
补偿在修改前检查所有引用的实体和组件。

**历史记录每次执行产生的实体身份。** 重做用成功结果里的补偿替换旧记录，
不保留上一次实体的代际。失败的撤销或重做将记录保留在原栈，允许重试。
新的可逆编辑和显式删除清空 redo；保存文件不丢弃 redo。

离散的 UI 操作调用 `perform`；键盘快捷键调用 `undo` 和 `redo`。
Gizmo 增量直接写入以提供同帧反馈，手势结束后记录一个补偿。
[Inspector 字段事务](../bug-fix/2026-10-16-inspector-edit-transactions.zh.md)
使用同一历史接口。渲染帧交接不属于该接口。

## Alternatives considered

**在 World 层实现撤销。** 未采用：任意组件删除没有类型化逆操作，world 修改
也不能标识用户操作。

**用用户动作批次表示补偿。** 未采用：移除导入实体是有效补偿，但允许用户批次
包含删除会使回滚承诺失效。独立类型表达这一区别。

**隐式处理部分失败。** 未采用：仅返回原始错误会掩盖回滚失败，调用方无法区分
已恢复状态与部分状态。补偿错误属于结果的一部分。

**每个拖拽帧对应一个撤销记录。** 未采用：合并手势能保留用户操作语义，避免
中间增量充满历史记录。

## Consequences

- 导入和场景加载使用当前实体代际支持重复撤销/重做；失败的历史操作可以重试。
- 删除和保存作为独立动作执行，不进入可逆批次。
- 无窗口测试与 UI 使用相同的执行和补偿接口。
- 删除丢弃任意组件，不可逆。Hook 和模板副作用
  没有通用回滚机制。
